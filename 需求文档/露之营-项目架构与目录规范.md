# 露之营项目架构与目录规范

## 1. 总体原则

- 网页端与小程序端共享一个 Java 后端。
- 网页端前端和管理后台前端放在同一个 Vue 项目内。
- 小程序端本次只建立骨架，不开发完整业务页面。
- 历史 Next.js 原型不再继续演进，统一归档到 `legacy/next-prototype`。

## 2. 目录规范

```text
luying/
├─ 需求文档/
├─ 网页版/
│  ├─ frontend/
│  └─ backend/
├─ 小程序版/
│  └─ frontend/
└─ legacy/
   └─ next-prototype/
```

## 3. 各目录职责

### 3.1 `网页版/frontend`

- 承载用户端页面
- 承载管理后台页面
- 只处理视图、路由、状态、API 请求
- 不放数据库脚本，不放后端业务实现

### 3.2 `网页版/backend`

- 承载网页端与小程序端共用的业务接口
- 承载权限控制、数据访问、DTO/VO、统一返回结构
- 承载 SQL 初始化脚本

### 3.3 `小程序版/frontend`

- 承载小程序前端骨架
- 与网页端共用后端接口约束
- 不复制后端逻辑

### 3.4 `legacy/next-prototype`

- 仅用于保存旧原型和字段参考
- 不再作为正式实现主线

## 4. 接口共享原则

- 用户基础接口由网页端和小程序端共用
- 小程序仅在确有移动端特性需求时再增加 `/api/app/*`
- 不允许为网页和小程序分别复制一套完全等价的接口

## 5. 数据与部署关系

- MySQL 作为统一主库
- Java 后端作为唯一业务入口
- Vue 前端与小程序前端都通过 HTTP API 访问后端

## 6. 后续扩展建议

- 二期引入 Redis
- 三期再评估对象存储、搜索服务和地图 SDK
- 微服务拆分不纳入当前 MVP
